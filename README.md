# Booking Bot — онлайн-запись в Telegram

Бот для барбершопа, салона, репетитора и другого небольшого бизнеса. Клиент выбирает
услугу и свободное время, оставляет контакты и подтверждает запись. Владелец получает
уведомления и управляет расписанием прямо в Telegram.

Один шаблон можно настроить под разные бизнесы через `.env` и `config/business.json`,
без изменения кода. В комплекте — пример вымышленного барбершопа **«Бритва»** с двумя мастерами.

## Возможности

**Для клиента:**

- Выбор услуги с ценой и длительностью.
- Выбор мастера или варианта «Любой свободный». Если подходит только один мастер, этот шаг пропускается.
- Только доступные даты и время: бот учитывает рабочие часы, перерывы, выходные и занятые записи.
- Ввод имени и телефона вручную или отправка своего контакта кнопкой.
- Предложение прошлого имени при следующей записи.
- Сводка перед подтверждением, список будущих записей и самостоятельная отмена до установленного срока.
- Напоминания за 24 часа и за 2 часа до визита.

**Для владельца:**

- Уведомления о новой записи и об отмене клиентом.
- Расписание на сегодня и завтра по мастерам, количество записей на неделю.
- Отмена записи с уведомлением клиента.
- Необязательный экспорт новых записей в Google Sheets.

**Для надёжности:**

- Повторная проверка слота и сохранение в одной транзакции SQLite.
- Защита от повторного подтверждения и ответы на устаревшие кнопки.
- Восстановление напоминаний и повтор неудачных выгрузок после перезапуска.
- Логи в консоль и файл с ротацией, общий обработчик ошибок.
- Ошибка уведомления владельцу или экспорта не отменяет сохранённую запись.

## Быстрый запуск

Нужны Python 3.11 или новее, доступ к Telegram и токен от [@BotFather](https://t.me/BotFather).
Команды ниже предназначены для macOS/Linux.

### 1. Установить проект

```sh
git clone https://github.com/kotysheff/booking-bot.git
cd booking-bot
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Копируй шаблон только при первой настройке: не перезаписывай уже заполненный `.env`.

### 2. Настроить Telegram

1. Создай бота через BotFather и вставь его токен в `BOT_TOKEN` файла `.env`.
2. В `ADMIN_CHAT_ID` укажи числовой ID своего личного Telegram-чата.
   Его можно узнать, например, через [@userinfobot](https://t.me/userinfobot).
3. Открой созданного бота в Telegram и нажми «Старт». Владелец должен первым начать
   диалог, чтобы бот мог отправлять ему уведомления.
4. Проверь услуги, мастеров и расписание в `config/business.json`.

Для первого запуска достаточно заполнить `BOT_TOKEN` и `ADMIN_CHAT_ID`.
Остальные поля можно оставить пустыми: включатся значения по умолчанию, экспорт будет выключен.
Токен и ключ Google храни локально, не публикуй в репозитории или сообщениях.

### 3. Запустить

```sh
python -m bot.main
```

Открой бота, отправь `/start` и пройди запись. Для остановки в терминале — Ctrl+C.
Запускай только одну копию бота с одним токеном и базой.

При старте проверяются настройки бизнеса и окружения. При ошибке бот завершится
с пояснением. База и таблицы создаются автоматически при первом корректно настроенном запуске.

## Настройки окружения

Шаблон — [.env.example](.env.example).

| Поле | Обязательно | Значение |
| --- | --- | --- |
| `BOT_TOKEN` | Да | Токен бота от BotFather |
| `ADMIN_CHAT_ID` | Да | Числовой ID чата владельца |
| `TIMEZONE` | Нет | Часовой пояс; по умолчанию `Europe/Moscow` |
| `DB_PATH` | Нет | Путь к базе; по умолчанию `data/bot.db` |
| `GOOGLE_SHEET_ID` | Для экспорта | ID Google-таблицы, а не полный URL |
| `GOOGLE_CREDENTIALS_PATH` | Для экспорта | Путь к JSON-ключу сервисного аккаунта |

Пустые поля `TIMEZONE` и `DB_PATH` используют значения по умолчанию.
Относительные пути считаются от папки проекта. Переменные, уже заданные в окружении
процесса, имеют приоритет над `.env`.

Все времена хранятся в UTC и показываются в `TIMEZONE`. Часовой пояс указывается
именем, например `Europe/Moscow`, а не смещением вроде `UTC+3`.

Поля Google заполняются вместе: оба пустые — экспорт выключен; заполнено только одно —
бот не стартует и сообщает, что нужно исправить.

## Настройка бизнеса

Основной файл — [config/business.json](config/business.json). После изменений перезапусти бота.

| Поле | Назначение | По умолчанию |
| --- | --- | --- |
| `name` | Название бизнеса | Обязательно |
| `texts.welcome` | Приветствие | Обязательно |
| `texts.thanks` | Сообщение после записи | Обязательно |
| `texts.cancel_rules` | Правила отмены и способ связи | Обязательно |
| `services` | Услуги | Хотя бы одна |
| `masters` | Мастера и расписание | Хотя бы один |
| `days_off` | Общие выходные в формате `ГГГГ-ММ-ДД` | `[]` |
| `slot_step_minutes` | Шаг сетки от начала смены | `30` |
| `booking_horizon_days` | Число календарных дней для записи, включая сегодня | `14` |
| `min_lead_minutes` | Минимальное время от записи до визита | `120` |
| `cancel_deadline_minutes` | Граница самостоятельной отмены | `180` |

### Пример минимального конфига

```json
{
  "name": "Студия",
  "texts": {
    "welcome": "Привет! Выбери услугу и удобное время.",
    "thanks": "Запись подтверждена. Ждём тебя!",
    "cancel_rules": "Отмена доступна более чем за 3 часа. Позже свяжись с администратором."
  },
  "services": [
    {"id": "haircut", "name": "Стрижка", "duration_minutes": 60, "price": 1500}
  ],
  "masters": [
    {
      "id": "alex",
      "name": "Алексей",
      "services": ["haircut"],
      "working_hours": {
        "mon": ["10:00", "19:00"],
        "tue": ["10:00", "19:00"],
        "wed": ["10:00", "19:00"],
        "thu": ["10:00", "19:00"],
        "fri": ["10:00", "19:00"]
      },
      "breaks": {
        "mon": [["13:00", "14:00"]],
        "tue": [["13:00", "14:00"]],
        "wed": [["13:00", "14:00"]],
        "thu": [["13:00", "14:00"]],
        "fri": [["13:00", "14:00"]]
      }
    }
  ],
  "days_off": [],
  "slot_step_minutes": 30,
  "booking_horizon_days": 14,
  "min_lead_minutes": 120,
  "cancel_deadline_minutes": 180
}
```

Укажи в `cancel_rules` реальный телефон или способ связи. Этот текст редактируется
вручную: если меняешь срок отмены, обнови и текст.

### Услуги, мастера и расписание

- У услуги есть уникальный `id`, название `name`, длительность `duration_minutes` и цена `price` в рублях.
- У мастера — уникальный `id`, имя `name`, список ID услуг `services`, часы `working_hours` и перерывы `breaks`.
- ID содержат до 24 латинских букв, цифр, `_` или `-`. Значение `any` зарезервировано.
- Дни недели: `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`. Неуказанный день — выходной.
- Время задаётся как `ЧЧ:ММ`, рабочий интервал — парой начала и конца. Ночные смены не поддерживаются.
- Перерывы должны находиться внутри рабочего дня и не пересекаться. Можно указать несколько перерывов.
- `days_off` закрывает указанную дату для всех мастеров.
- Услуга целиком должна помещаться до перерыва или конца смены.

Например, при смене с 10:00, шаге 30 минут и услуге длительностью час сетка начинается
с 10:00, 10:30, 11:00. Время, пересекающее перерыв или занятую запись, не показывается.

Минимальное время до визита включительно: при `min_lead_minutes: 120` можно записаться
ровно за два часа. При горизонте 14 дней доступны сегодня и следующие 13 календарных дней.

Не меняй ID услуг и мастеров, пока есть будущие записи. Изменение графика не отменяет
уже подтверждённые записи. Названия и цены в сообщениях берутся из текущего конфига:
менять их для действующих записей нужно с учётом договорённостей с клиентами.

## Сценарий клиента и команды

1. `/start` → «Записаться».
2. Выбор услуги.
3. Выбор подходящего мастера или «Любой свободный».
4. Выбор даты со свободными слотами и времени.
5. Ввод имени или выбор прошлого имени.
6. Телефон: своим контактом через кнопку или вручную.
7. Проверка сводки → «Подтвердить» или «Начать заново».
8. Сообщение с деталями и кнопкой отмены.

Номера `8XXXXXXXXXX` и `7XXXXXXXXXX` приводятся к `+7XXXXXXXXXX`.
Международный номер вводится с `+`; пробелы, скобки и дефисы удаляются.
Имя ограничено 2–80 символами. На неподходящее сообщение бот даёт подсказку.

### Клиент

| Действие | Результат |
| --- | --- |
| `/start` | Сброс текущего шага и главное меню |
| `/cancel` | Сброс текущего шага; сохранённая запись остаётся |
| «Мои записи» | Будущие активные записи клиента |
| «Отменить запись» | Отмена, если срок ещё позволяет |

При `cancel_deadline_minutes: 180` отмена доступна **более чем за 3 часа**.
Ровно за 3 часа и позже бот показывает «Отмена только по телефону».
Позднюю отмену может сделать владелец до начала визита.

### Владелец

| Команда или кнопка | Результат |
| --- | --- |
| `/today` | Расписание на сегодня по мастерам, с контактами клиентов |
| `/tomorrow` | Расписание на завтра |
| `/week` | Количество активных записей по дням на 7 дней, включая сегодня |
| «Отменить запись» под записью в расписании | Отмена с уведомлением клиента |

Команды владельца доступны только в `ADMIN_CHAT_ID`: остальным они не показываются
в меню команд и не выполняются из другого чата. Используй личный чат владельца:
доступ проверяется по ID чата, а не по участнику группы.

## Защита от двойной записи

Выбор времени ещё не резервирует слот. При подтверждении бот снова рассчитывает
доступность с учётом актуальных записей.

Проверка и вставка выполняются в одной транзакции SQLite с `BEGIN IMMEDIATE`:
два клиента не могут сохранить пересекающиеся записи к одному мастеру.
У подтверждения есть уникальный ключ, поэтому повторное нажатие не создаёт дубль.
Соседние записи без пересечения допустимы: одна может начинаться ровно в момент окончания другой.

Если слот успели занять, бот предлагает оставшееся время на ту же дату.
Если свободных слотов больше нет — предлагает другую дату.
При варианте «Любой свободный» мастер назначается из доступных на момент подтверждения.

## Напоминания и перезапуски

Напоминания отправляются за 24 часа и за 2 часа до визита, с кнопкой отмены.
Если запись создана меньше чем за 24 часа, первое напоминание не создаётся.
Если до визита осталось меньше двух часов, напоминание за 2 часа также не создаётся.

При запуске бот читает подтверждённые записи из SQLite и восстанавливает задачи.
Пропущенные во время остановки напоминания отправляются, пока визит ещё не начался.
Неудачная отправка повторяется через периодическую проверку раз в минуту.
После отмены задачи удаляются; перед отправкой статус проверяется повторно.

Незаконченный диалог хранится в памяти и после перезапуска начинается заново через `/start`.
Сохранённые записи остаются в базе.

Отправка сообщения и отметка в SQLite не являются одной транзакцией:
при аварии между этими действиями напоминание может повториться.
Если пользователь заблокировал бота, доставить ему сообщения невозможно.

## Экспорт в Google Sheets

Экспорт необязательный: без него запись, отмены и напоминания работают самостоятельно.

### Подключение

1. В Google Cloud создай или выбери проект и включи **Google Sheets API** и **Google Drive API**.
2. Создай сервисный аккаунт, затем JSON-ключ для него.
3. Сохрани ключ вне Git. Файл `credentials.json` в корне проекта уже исключён через `.gitignore`.
   Если используешь другое имя, храни его вне репозитория или добавь в исключения.
4. Создай отдельную Google-таблицу. Дай адресу `client_email` из ключа права редактора.
5. Заполни оба поля в `.env`:

```dotenv
GOOGLE_SHEET_ID=идентификатор_таблицы
GOOGLE_CREDENTIALS_PATH=credentials.json
```

ID находится в URL таблицы между `/d/` и `/edit`. Полный URL и `gid` листа не подходят.
Настройка сервисного аккаунта описана в [документации gspread](https://docs.gspread.org/en/latest/oauth2.html#for-bots-using-service-account).

### Какие данные выгружаются

На первый лист таблицы добавляются:

| Колонка | Содержимое |
| --- | --- |
| ID записи | Уникальный ID из базы бота |
| Создана (UTC) | Время создания записи |
| Начало, конец | Время визита с часовым поясом |
| Часовой пояс | Значение `TIMEZONE` |
| Услуга, мастер | Названия из конфига |
| Имя, телефон | Контакты клиента |
| Telegram ID, username | Данные Telegram |

Пустой лист получает заголовки. Значения передаются с `value_input_option='RAW'`,
поэтому введённый клиентом текст не исполняется как формула.

Это журнал новых записей: последующие отмены уже выгруженных записей не обновляются.
Первая колонка нужна для защиты от дублей при перезапуске — не меняй и не удаляй её.
Одна таблица должна обслуживать одну базу: в разных базах могут совпасть ID записей.

### Повторные попытки

Проверка выполняется при запуске и затем раз в минуту. При доступном Google экспорт
обычно происходит на ближайшем проходе. Сбой не отменяет запись и не ставит отметку об успехе.
Все записи с `sheet_exported=0` остаются в очереди, включая отменённые и уже прошедшие.
Ошибка одной записи не мешает выгрузке остальных.

В логе есть ID записи и результат:

```text
ERROR bot.services.sheets: Экспорт записи 12 не удался: ConnectionError
INFO bot.services.sheets: Повторная попытка экспорта записи 12 в Google Sheets
INFO bot.services.sheets: Запись 12 успешно экспортирована в Google Sheets
```

Отметка об успехе сохраняется в SQLite. История неудач для сообщения «Повторная попытка»
хранится в памяти текущего процесса; после перезапуска очередь восстанавливается из базы,
а при первой попытке отдельного сообщения о повторе может не быть.

## Логи и разбор ошибок

Логи записываются в консоль и `logs/bot.log`. Ротация: до 2 МБ на файл,
три резервных файла. Для просмотра при локальном запуске:

```sh
tail -f logs/bot.log
```

Необработанная ошибка попадает в лог, клиент получает сообщение «Что-то пошло не так»
и может вернуться через `/start`. Неудачное уведомление владельцу не откатывает запись.

| Симптом | Что проверить |
| --- | --- |
| Ошибка `BOT_TOKEN` при запуске | Поле заполнено токеном от BotFather, без лишних пробелов |
| Ошибка `ADMIN_CHAT_ID` | Указан числовой ID, а не username |
| Нет уведомлений владельцу | Владелец открыл именно этого бота и нажал «Старт»; ID указан верно |
| Нет свободных дат | Мастер делает услугу, работает в эти дни; длительность помещается до перерыва/закрытия; не мешают `days_off`, горизонт, минимальное время до визита и занятые записи |
| «Отмена только по телефону» | До визита осталось не больше `cancel_deadline_minutes` |
| `SpreadsheetNotFound` | Верный ID таблицы и доступ редактора у `client_email` именно из используемого JSON-ключа |
| `ConnectionError` при экспорте | Доступ сервера к Google, DNS и сеть; невыгруженная запись остаётся в очереди |
| Заполнено только одно поле Google | Заполни оба поля или очисти оба |
| Не найден JSON-ключ | Проверь `GOOGLE_CREDENTIALS_PATH`, путь считается от корня проекта |
| Неизвестный `TIMEZONE` | Используй имя из базы часовых поясов, например `Europe/Moscow` |
| Конфликт polling | Останови вторую копию бота с тем же токеном |
| Ошибка записи в базу или логи под systemd | Проверь владельца папок и `ReadWritePaths` в юните |
| После перезапуска кнопка устарела | Открой `/start`; сохранённые записи доступны в «Мои записи» |

## Тесты

```sh
.venv/bin/python -m unittest discover -v
```

Тесты используют временные базы и подменённые ответы Telegram/Google.
Они не запускают polling, не требуют токена и не отправляют реальные сообщения.

Покрыты:

- Валидация конфигов, значения по умолчанию и неполные настройки Google.
- Рабочие часы, перерывы, выходные, общие нерабочие даты, длительность услуги,
  минимальное время до визита, горизонт и пересечения записей.
- Часовые пояса и несуществующее местное время при переводе часов.
- Одновременная запись нескольких клиентов и повторное подтверждение.
- Нормализация телефона, ввод имени, обработка неподходящих сообщений.
- Полный сценарий через обработчики aiogram, устаревшие кнопки, права владельца и отмены.
- Время напоминаний, восстановление, повтор отправки и отменённые записи.
- Экспорт без дублей, INFO-логи и повтор после `SpreadsheetNotFound` и `ConnectionError`,
  включая перезапуск, прошедшие и отменённые записи.

Тесты не заменяют проверку своего токена, доступа Google и реальной доставки сообщений.

## Развёртывание на Linux

В проекте есть [systemd-юнит](deploy/booking-bot.service) для пользователя `booking-bot`
и папки `/opt/booking-bot`. Ниже пример для сервера с systemd и установленными
Python 3.11+, модулем `venv` и Git. Команды выполняются на сервере.

### Подготовка

Создай отдельного пользователя и размести проект:

```sh
sudo useradd --system --user-group --home-dir /opt/booking-bot --shell /usr/sbin/nologin booking-bot
sudo git clone https://github.com/kotysheff/booking-bot.git /opt/booking-bot
sudo chown -R booking-bot:booking-bot /opt/booking-bot
sudo -u booking-bot python3 -m venv /opt/booking-bot/.venv
sudo -u booking-bot /opt/booking-bot/.venv/bin/python -m pip install -r /opt/booking-bot/requirements.txt
sudo -u booking-bot cp /opt/booking-bot/.env.example /opt/booking-bot/.env
sudo -u booking-bot mkdir -p /opt/booking-bot/data /opt/booking-bot/logs
sudo chmod 600 /opt/booking-bot/.env
```

Заполни `.env`, проверь `config/business.json`. При включённом экспорте сохрани ключ,
дай пользователю `booking-bot` право чтения и закрой доступ для остальных пользователей.
Пример для `/opt/booking-bot/credentials.json`:

```sh
sudo chown booking-bot:booking-bot /opt/booking-bot/credentials.json
sudo chmod 600 /opt/booking-bot/credentials.json
```

### Установка сервиса

```sh
sudo cp /opt/booking-bot/deploy/booking-bot.service /etc/systemd/system/booking-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now booking-bot
sudo systemctl status booking-bot
sudo journalctl -u booking-bot -f
```

Сервис запускается после загрузки системы и перезапускается после сбоя.
Для применения изменений настроек:

```sh
sudo systemctl restart booking-bot
```

Юнит ограничивает запись папками `data` и `logs`. При изменении `DB_PATH`
добавь нужную папку в `ReadWritePaths`. При смене папки проекта обнови также
`WorkingDirectory` и `ExecStart`. `ProtectHome=true` закрывает доступ к домашним
папкам: ключ Google для этого юнита лучше хранить внутри `/opt/booking-bot`.
На macOS systemd-юнит не используется.

## Обновление и резервные копии

База содержит имена, телефоны и записи клиентов. Не публикуй её вместе с кодом.

Для простой резервной копии:

1. Останови бота (`sudo systemctl stop booking-bot` на сервере).
2. Скопируй файл из `DB_PATH` в отдельное защищённое место.
3. Сохрани резервные копии `.env`, конфига бизнеса и ключа Google отдельно от публичного репозитория.
4. Запусти бота (`sudo systemctl start booking-bot`).

Для обновления сервера останови сервис, сделай резервную копию, получи изменения
из Git, установи зависимости из `requirements.txt`, запусти тесты и снова запусти сервис.
Не удаляй базу и не заменяй заполненный `.env` шаблоном.

Если `config/business.json` изменён под реальный бизнес, перед получением обновлений
сохрани свою версию и проверь возможные конфликты. При восстановлении базы после
успешных выгрузок также учитывай ID записей в Google Sheets.

## Ограничения

- Один процесс бота на токен и базу; состояния диалога хранятся в памяти.
- Запись работает в личном диалоге. Для владельца предусмотрен доступ по ID чата.
- Рабочая смена должна начинаться и заканчиваться в один календарный день.
- Оплаты, переноса записи, веб-панели и редактирования расписания из Telegram нет.
- Google Sheets хранит журнал новых записей, без синхронизации последующих отмен.
- Сбой между отправкой напоминания и отметкой в базе может привести к повторному сообщению.

Перед использованием с клиентами проверь на своём боте запись и отмену обеими сторонами,
одновременный выбор слота, права владельца, доставку напоминаний после перезапуска
и доступ к Google Sheets, если экспорт включён.
